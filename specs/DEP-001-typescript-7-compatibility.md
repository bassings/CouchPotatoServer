# DEP-001 — adopt TypeScript 7 without disabling the E2E false-green guard

## Problem

Dependabot PR #359 changes `typescript` from 6.0.3 to 7.0.2. The update is not
a routine major bump: TypeScript 7 is a native compiler and deliberately ships
without the JavaScript compiler API. `scripts/check_e2e_test_traps.mjs` imports
that API and uses `createSourceFile`, `createProgram`, `getTypeChecker`, and AST
type guards to reject vacuous Playwright tests.

The unmodified update was reproduced locally and in CI. `ScriptTarget` and
`createSourceFile` are undefined, the guard fails on 28 E2E files, and the
required lint, Python-test, and summary jobs fail. Weakening or skipping that
guard is not an acceptable migration.

Microsoft's TypeScript 7 guidance provides a transition mechanism:
`@typescript/typescript6` supplies the TypeScript 6 API alongside the native
TypeScript 7 compiler. The repository will adopt that split explicitly.

## Chosen design

Use two exact, independently named development dependencies:

- `@typescript/native: npm:typescript@7.0.2` owns the native `tsc` executable.
- `@typescript/typescript6: 6.0.2` owns the compatibility API and `tsc6`.

The AST helper will import `@typescript/typescript6` directly. It will not rely
on a package named `typescript` ambiguously meaning either the native compiler
or the legacy API. This is the smallest honest boundary for this repository:
the dependency graph has no tool that currently needs a `typescript` peer, and
the one API consumer is under our control.

The compatibility wrapper is version 6.0.2 but depends on
`@typescript/old: npm:typescript@^6`; the lockfile, not an assumed wrapper
version, determines the exact API implementation. Tests therefore verify both
the exact direct dependency/lock and the required API behavior.

## Acceptance criteria

- **AC-ARCH-1:** `package.json` contains exact (no range) dev dependencies for
  `@typescript/native` aliased to `typescript@7.0.2` and
  `@typescript/typescript6@6.0.2`; the old direct `typescript` entry is absent.
  `package-lock.json` is regenerated by npm and contains integrity-protected
  official registry artifacts without unrelated dependency churn.
- **AC-ARCH-2:** `scripts/check_e2e_test_traps.mjs` imports only
  `@typescript/typescript6` for compiler-API work. Its restricted compiler host,
  `noLib`, and `noResolve` boundaries remain unchanged.
- **AC-QA-1:** A dependency-contract test executes the installed local binaries
  (never a network-fallback `npx` invocation): TypeScript 7's `tsc --version`
  reports 7.0.2, `tsc6 --version` and the imported API's `version` both report
  exactly 6.0.3, and the compatibility module exposes callable
  `createSourceFile`, `createProgram`, and the AST predicates the guard
  consumes. The test creates a program and proves its `getTypeChecker()` method
  works. The lock entry for `@typescript/old` is pinned by the
  same assertion so the wrapper's `^6` dependency cannot silently downgrade or
  advance the API implementation.
- **AC-QA-2:** The contract test proves the native compiler is functional, not
  merely present: it accepts a valid typed fixture and rejects an invalid
  assignment with a type diagnostic and non-zero exit.
- **AC-QA-3:** The existing Rule 6 positive/negative corpus remains green,
  including symbol-isolation and expected-zero false-positive cases, and the
  real-tree `--require-git` trap scan passes over every tracked E2E file.
- **AC-QA-4:** Missing/wrong compatibility APIs and helper subprocess failures
  preserve the actionable exception and produce a non-zero command result;
  they must never be converted into an empty finding set or a passing scan.
  Global deduplication across the per-file helper invocations is not required.
- **AC-QA-5:** `scripts/verify.sh`, the relevant hosted CI jobs, and the Alpine
  local-test path perform a locked install before invoking their consumers.
  Local preflight checks cover both named packages. Standalone
  `make check-traps` remains non-mutating and fails clearly if dependencies are
  absent. No check uses a globally installed compiler or permits npm to
  download a missing executable on demand.
- **AC-SEC-1:** Both packages remain development-only. A contract assertion
  verifies the installed TypeScript wrapper, native package, and selected
  platform package declare no lifecycle scripts; the existing Alpine
  `scripts/test-local.sh` path continues to install with
  `npm ci --ignore-scripts`. Package provenance is recorded from npm metadata,
  the declared Microsoft repository, and the lockfile's registry URLs, exact
  versions, and integrity hashes. The hosted dependency-review check separately
  passes its vulnerability/license policy. Other npm-install policy is not
  broadened by this migration.
- **AC-SEC-2:** A regression test preserves the helper's local parse-only
  boundary: imported source text cannot cause adjacent-file/package resolution,
  or execution of the inspected test code.
- **AC-OPS-1:** The native compiler is exercised by the documented Alpine
  local-test path before push and by the existing hosted Ubuntu CI install/test
  jobs after push. An absent or unsupported native binary produces a named
  dependency/platform failure rather than falling back to TypeScript 6 or
  skipping the check; this task does not add another hosted CI job.
- **AC-OPS-2:** When the Node helper fails with multiline stderr ending in a
  generic runtime/version line, `check_test_traps.py` retains the actionable
  exception rather than reporting only the final `Node.js v…` line. A focused
  regression test pins that diagnostic behavior.
- **AC-MUT-1:** Deliberately swapping the native and compatibility dependencies
  fails the dependency/API contract; changing the invalid compiler fixture to
  valid fails its assertion; suppressing helper failure propagation fails the
  fail-closed tests. Each mutation is restored before the final green run.
- **AC-SIMP-1:** No new wrapper script, build system, `tsconfig`, runtime
  dependency, or broad source conversion is introduced. The change is limited
  to the dependency split, the single API import/preflight, the narrow
  actionable-stderr preservation fix, and focused tests.

## TDD and delivery sequence

1. Record the current green Rule 6 corpus and real-tree trap scan.
2. Add the dual-runtime behavior/contract tests first. Confirm red because the
   native alias and compatibility package are absent.
3. Add the exact dependencies with npm and regenerate the lockfile. Update the
   helper import and local preflight; make the contract and corpus green.
4. Add fail-closed and parse-isolation cases before any production guard change
   they require. Keep the existing compiler-host restrictions intact.
5. Run the three deliberate mutations in AC-MUT-1, restore them, then run the
   focused unit suite, real-tree trap scan, `npm ci`, and the full local gate.
6. Run at least two independent local code reviews. Fix, re-verify, and repeat
   until clean; then push a replacement PR linked to closed Dependabot PR #359.
7. Run the Alpine local-test path before push, then require all hosted CI checks
   (including Ubuntu dependency review and tests) to pass before squash merge.

## Expected files

- `package.json`
- `package-lock.json`
- `scripts/check_e2e_test_traps.mjs`
- `scripts/check_test_traps.py`
- `scripts/verify.sh`
- `tests/unit/test_check_test_traps.py`
- optionally one small typed fixture under `tests/fixtures/` if an inline
  temporary fixture would obscure the compiler-behavior test

## Explicitly out of scope

- Removing the AST false-green guard or replacing syntax-aware analysis with
  regexes.
- Migrating the application or Playwright tests to a new TypeScript build.
- Introducing a repository-wide `tsconfig.json` solely to make the new compiler
  appear used.
- Relaxing required CI, `--fail-on-flaky-tests`, dependency review, or local
  review gates.
- Waiting silently for TypeScript 7.1. The compatibility boundary is temporary,
  but it is explicit and tested; revisit it when TypeScript exposes its new API.

## Evidence and rollback

- PR #359 is the red baseline and must remain linked from the replacement PR.
- Microsoft documents that TypeScript 7.0 has no API and recommends running the
  TypeScript 6 compatibility package side by side.
- Rollback is one commit: restore TypeScript 6.0.3 and the original helper
  import. Do not retain half of the dual-runtime topology.
