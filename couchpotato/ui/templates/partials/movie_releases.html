{# Movie detail release list. Rendered inline by movie_detail.html for first paint, and standalone by GET /partial/movie//releases for htmx swaps, so it must not depend on anything movie_detail.html computes locally -- every variable it uses (movie_id, title, releases, total_releases, raw_release_count, controls, options, columns) is supplied by _releases_ctx() in couchpotato/ui/__init__.py for both callers. The container itself always renders so it stays a stable htmx swap target and the controls never disappear out from under the user. There are three distinct states, and they must not collapse into each other -- a movie with releases the profile hides looks identical to "no releases yet" if they do, and the second is the actionable one (the user CAN see it if they widen the profile; there is nothing to do about the first): - raw_release_count == 0 (the movie has no releases at all yet): nothing renders -- there is nothing to filter, nothing to explain (FEAT-007 B14). - raw_release_count > 0 but total_releases == 0 (every release exists but none match the movie's quality profile): a heading plus an explanatory message renders, no controls or table -- filtering/ sorting an empty set has nothing to offer. - total_releases > 0: controls + table render as below. If the CURRENT FILTER (not the profile) matches nothing, controls stay visible with a "Clear filters" escape hatch, plus a "0 of N releases" live-region count. The releaseDownloader() Alpine component lives in movie_detail.html (loaded once per full page render), not here -- see the comment there for why. #release-count-announcer (WCAG 4.1.3): a filter/sort change swaps `#movie-releases`'s entire outerHTML, so an `aria-live` region nested inside it is destroyed and a brand-new node is inserted on every interaction -- screen readers do not announce a node they never saw "change" (they only announce mutations to a region that was already registered in the accessibility tree). The visible "N of M releases" count below stays where it is (sighted users see the swap happen), but a second, screen-reader-only copy lives as a SIBLING of `#movie-releases`, never touched by that swap, and is updated via `hx-swap-oob="innerHTML"` -- htmx scans the whole response for out-of-band targets regardless of the primary hx-target, so this same response updates both. `innerHTML` (not the bare `hx-swap-oob="true"` outerHTML shorthand) is deliberate: outerHTML would still destroy and recreate the announcer node itself on every swap, which is exactly the bug this exists to fix -- only a swap that leaves the node's identity alone and changes just its text content is announced reliably. #}
